# Agent 角色契約

2026-09-24 角色稽核涵蓋 21 個編號 Agent、26 個模式配置和 6 類輔助角色。8–10 不在 registry。各模式流程維持 [pipeline-mode-contract.md](pipeline-mode-contract.md) 的定義，不因角色名稱相近合併。

研究情境仍使用原本 schema 欄位與 enum，沒有放寬價格、來源、逐字引用或品質檢查。條件計畫不等於已發生事實或個人化委託指示。

Agent 7 的初次分析與修復提示提供完整、分別歸屬 Agent 4／5 的字串原文，與引用驗證器使用同一組來源。引文不得改寫、跨角色或從財務 JSON 冒充；原文沒有相關假設仍須未評估。為控制容量，僅將兩個 preload 中與提示內財務 JSON 完全相同的同業資料改為內部路徑引用；不同日期、缺值、順序或型別維持完整資料。這不提高模型輸入上限，也不開啟全域 Gemma 壓縮旗標。

B 的完整度說明將研究缺口與部位評估分開：已記錄的逐字稿或角色未評估會指出具體缺口；缺資金本身只表示部位未評估。品質 gate 全過或沒有缺口標記，均不能代替逐角色來源完整度的認證。報告 snapshot 保留 workflow 明示的 `position_sizing_context` 供讀取時重算核對；不從模型輸出或 provider 資料反推資金，歷史缺少輸入的收據仍未確認。

C 的「持有」仍須符合既有估值與方向條件。純研究觀察且不新增部位時，Agent 19 應明確表達該決策並使正文、進場條件與回補停損一致；不得為迴避警示而改推薦或補造目標價。歷史報告警示維持原證據判定。

Agent 7 的引文只有在同角色、當前上游來源可唯一還原連續原文字串時，才容許補回來源中的成對 `**` 粗體符號；不補字、不改數字／空白／標點、不跨段或跨來源拼接。其餘逐字與狀態檢查照常執行，修復回饋須指出失敗的 topic／field。`assumption_quote_restoration` 是本地格式轉換收據，記錄輸入、前後引文與來源雜湊／位置，不能證明投資結論正確，也不能讓歷史或模型自填收據授權新引文。

Agent 7 的初稿與修復提示共用無損表示法：完整財務 JSON 可使用既有 record-table／同值 freshness 引用，只有逐路徑與型別還原相等且包含解碼規則後仍節省輸入時才採用；來源內自帶的格式標記、重複 JSON key 或不確定表示保留原文。前序片段先依原預算選取，再只壓縮開頭系統 JSON 區塊的空白，不改引文字串或擴大選取範圍。同角色 catalog 中完整包含於另一原字串的葉值可省去重複展示，但 validator 與格式還原收據仍使用原始完整來源；跨角色、近似或片段拼接不可去重。64k 本機 admission 與其餘品質檢查照常執行，較大資料仍可能超限。

Agent 7 的 `gemini-3-flash-preview` 備援明確使用 `thinking_level=low`，維持 6144 輸出 token 上限及原重試次數；其他模型的思考設定不變。系統指令優先完整 JSON，精煉正文目標不得省略來源評估、反證或逐字引文；五項假設對照 topic 與 schema 共用既有契約。Google 的輸出上限包含思考用量，low 是相對設定而非完成保證；缺少 usage 時不得倒推出實際思考 token 數量。實際完成性仍以 provider 結束原因、原始 JSON、品質 gate 與正式 artifact 為證。

Agent 7 的已知未完成回應與未閉合 JSON 不得由語法修補升格為完整 structured output。完成性收據綁定原始回應及本地清洗雜湊，二次解析、未驗證草稿的冷恢復及失敗修復回滾須保留這項事實；新回應不繼承不相符的舊收據。step cache 排除不完整候選，正常完整稿仍可快取。不得從截斷稿拼接市場評估到已接受的報告；既有整份候選檢查、保守 fallback 及其資料不足警示保留。

Agent 7 的假設對照修復回饋須指出 topic、引文欄位、來源角色及原 status，區分非逐字片段與「空引文卻宣稱 aligned／conflict」。來源缺少對應證據時應由模型如實說明 unassessed；有證據時只能引用同角色的連續原文，不可省略或拼接。頂層 status 與 pending_recalculation 仍由既有契約檢查，回饋不代替模型改寫任何狀態、推薦或價格；必須重寫並重新驗證完整候選，保留原修復上限與整份報告 gate。

Agent 7 的 step cache 也排除已有假設對照 assessment issues 的完整候選，讀取舊項目、寫入新項目及恢復時皆套用；已知失敗稿會走既有模型路由重新生成，不重用它消耗修復次數。合法且無契約錯誤的 unassessed 或 conflict 仍可快取，並繼續接受下游品質檢查。這項規則不清除既有快取或額度保護，也不代表無 issues 即為整份報告品質通過。

C 的完整「本研究情境不建立空方部位，回補停損不適用」與同義的明確無條件聲明應可原樣通過 normalization；其中獨立的「回補停損不適用」不是回補交易指令。純觀望豁免仍限明確「避免」及完整欄位，已有空單、未平倉、價格、條件交易或有條件不開倉不可被研究用語蓋過；N/A 不會自行補成無部位事實。這些變更更新 Agent 7／19 的 step-cache 契約，不清除既有額度或重試保護。

C 的無條件不開倉政策可帶有明確基本面重評條件，例如「等待單月營收未能突破 55 億元且毛利率未能回升之條件達成後再重新評估」。僅接受可完整辨識的營收／獲利率、單位與重評子句；未知數字、股價條件、交易指令仍不能視為無部位契約。數字及原句保留，並不因此證明門檻有來源支持。`scenario_triggers.action` 若同時聲稱開倉、持倉、回補或退出，既有 final audit 必須提出具體欄位問題供有界修復，內容可信度也不給純觀望豁免；來源引文與一般風險說明不當作使用者交易指令。

目標欄位明示 `N/A／未評估` 時，說明中的年份、歷史發行價、指標或舊目標都不能轉成這次目標價。此規則共用於品質檢查、目標追蹤、比較、回測與交易目標風控；現價等一般數字解析保留原語意。缺少目標及不開倉聲明不足時仍須警示，不能因為選擇「避免」就略過檢查。歷史 artifact 保留原樣，清單依當前規則呈現品質投影。

輔助角色：chief_editor 是 deterministic 整理；context_digest 僅壓縮已有證據；tear_sheet 是展示摘要；audit_reflection 提供修復指引但不能宣告 gate 通過；embedding 做檢索；Gemma evidence batching 為 22／23 摘取證據，不代替最終角色判斷。有效模型與能力以 [agent-effective-settings.md](agent-effective-settings.md) 的 API／worker 證據為準。

驗證使用隔離的 `tests/run_prompt_boundary_tests.py`，涵蓋角色提示、0／1／2／5 項反證、法人資料缺失／僅累計、負／零／正／無效 FCF、來源錯誤及生成截斷。這些契約檢查不等於所有供應商的即時成功率或全部新報告品質已驗收。

新風控適用新生成、修復、step cache 的品質入口、尚未驗證的 quality draft 與保守 fallback。既有正式報告及已成功完成節點的歷史 LangGraph checkpoint 不會因部署而自動重算。
