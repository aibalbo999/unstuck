## 503 共享退避

`llm_congestion.py` 僅將真實 HTTP 503 記為 server failure。共用 store 立即冷卻該模型，初次 60 秒加 jitter、連續失敗逐步至 300 秒加 jitter，較長 Retry-After 優先。冷卻期走現有健康備援；期滿只允許一個恢復 probe，成功重開。429 的不同 key 聚合與 RPD 排除維持原樣，503 不被當成 provider 日額度。

離線驗證使用 `tests/run_prompt_boundary_tests.py`。真實模型同資料驗證及正式部署另留帶日期證據；小樣本只能證明路徑可工作，不能推論全天 429／503 已消失。原始報告、snapshot 與 audit 記錄保留。
