# 門檻後台股分析

由 `NIGHTLY_TAIWAN_ANALYSIS_ENABLED=1` 明確啟用。現有台股 post_market 自動分析及同清單同模式事件雷達付費送件改由夜間批次處理；未被夜間範圍覆蓋的事件模式保留既有流程；18:00 選股範圍、資料追蹤及其他市場／盤前行為不擴張。舊派發與完成日期不清除。

22:35 至翌日 07:00 取得當晚交易日的來源，跨午夜固定原 session；週五可週六完成。休市／未知日不建立股票工作。只取批次首次建立時已啟用且含 post_market 的既有清單。每股票／模式／交易日固定一個工作 ID；原始資料先通過官方行情與法人 22:30 後收據、日期、股票、分項與日線交易日查核，再保存不可變輸入，之後才進入原分析 runner。取證失敗最多六次、間隔至少15分鐘，不呼叫模型。工作已執行或終止不自動另開新工作；供應商可用性重試沿用既有同工作checkpoint規則。

晨報依前一天交易日與新分析完成狀態判斷，不用報告保存日代替行情日。資料刷新、舊分析重播、degraded備援、品質blocked/rejected或來源不合格都不能算就緒。22:30不是交易所SLA，也不是PIT或完整財務驗證。固定76歷史批次不納入本流程。

回復：停用此環境開關並受控重載；保留夜間工作journal供查核，不刪工作、Redis或歷史資料。已排入的工作須先確認狀態，不能重送同一session。

就緒目前依既有可正向確認的 v4 來源／輸出契約，v3 完整度仍可能 unconfirmed；應逐檔讀 ready_count/items，不把整批 false 當成工作執行失敗。不放寬其他模式的完整度。日曆未知時不凍結空範圍，等日曆可核後再建立當日範圍。

夜間已有工作後的回復不可僅關旗即啟動正常排程：先受控停止服務，檢查夜間工作、佇列及既有 post_market 完成日期，避免回復舊派發器造成同日重複；保留 journal，不清除 DB 或 Redis。若需要改完成日期，需另做明確的逐筆回復操作。
