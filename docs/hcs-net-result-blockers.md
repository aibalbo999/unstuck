# 可驗證淨報酬缺口：第二階段

此批僅增加唯讀診斷及未來取得行情的 provenance，不回算歷史、不補成本為零、不把 provider SDK 設定當成交易所原始價格證明。

2026-10-02 台北上午、最近完整交易日 2026-10-01 的全索引台股 v4：858 份報告、1716 個 5/10 日觀察槽。互斥分區為待成熟676、有成交但驗證未保存118、無成交862、結果或計畫缺漏46、日內順序不明4、保存的契約失敗10。10筆契約失敗中8筆是無法模擬的條件式進場、2筆是不可執行價格契約；不能改稱缺行情。

118筆成交結果均未保存交易日、價格可比性與成本 evidence；此三項缺口可重疊，不能加總成354筆，也不能由此推定實際資料不存在。歷史結果沒有封存 raw bars，真實 provider 資料缺漏無法事後從缺 metadata 推導。固定10日、同股不重疊主集合166筆：待成熟76、有成交但驗證未保存16、無成交59、結果或計畫缺漏15。

`population.net_result_diagnostics` 對全索引與主集合分別提供互斥分區、保存的失败原因及可重疊合約缺口。已保存但現行交易日判定未成熟的結果不再混進主集合描述性樣本或可比淨結果計數；歷史列不改寫。

新行情行保存 provider、ticker、UTC取得時間、查詢起訖及 auto_adjust/actions 設定。評估結果保存回應內容SHA256、日期範圍及首筆 provenance；指紋不是原始行情封存，也不是取得當時可用性的證明。取得時間不回填成歷史 `available_at`。`auto_adjust=False` 只能證明請求設定，不能證明歷史價格已與交易所 split/raw basis 校準，所以仍標示 `provider_raw_basis_not_established`。公司行動欄位缺漏、None、NaN、無限、負數及布林值均不能當零事件。

後續需要：可保存且可核對的 raw/action 來源、報告進場價同一價格基準、事先明訂且有來源時間的佣金/稅/滑價（Short另含借券融資）、逐槽自然到期。情境成本可獨立比較但不能冒充真實成交；本批沒有建立成本費率、外部取價、歷史大量重算或 out-of-sample 盈利證據。現有 `scripts/evaluate_signal_increment.py` 是固定政策、控制組與 embargo 入口，仍需真正 point-in-time 資料。
