# Report price and volume basis reconciliation

## Verified problem and sample (2026-10-02 Taipei)

Three existing reports were sampled: 1301, 6456, and 1513. Archived official MI_INDEX date=20261002 response acquired 21:17:26 Taipei was compared with newly acquired Yahoo provider raw+Adj Close frames at 23:46:09 Taipei (these are later observations, not historical point-in-time proof). All four OHLC fields matched the official session to floating-point tolerance. Yahoo volume was lower than official by 48,838 / 31,375 / 10,185 shares respectively. The cause of volume scope differences remains unknown; no assumption about odd lots, corrections, dividend adjustments or trade categories is made. Six earlier 1513 rows had an Adj Close/Close factor different from one. The archived three-month sample does not verify the full five-year history.

The production short-term context normalizer discarded price_adjustment_basis while recalculating indicators. The report provider supplied adjusted-only OHLC, so a same-date current close could not independently establish raw OHLC equivalence. Same unit (shares) also did not establish equal volume scope.

## Producer and consumer changes

The existing five-year history request now asks for auto_adjust=False once. Taiwan requests record the verified completed session and an explicit exclusive end. Live verification exposed a latest-date row whose Close and Adj Close were both NaN; this was an upstream incomplete row, not a date revision. Only this missing-session condition invokes a cached same-provider one-session request. It must return the exact date, complete valid OHLC and a real Adj Close, and every previously known overlapping price/volume field must agree. Otherwise the original gap remains. No official close or assumed adjustment factor is inserted. Core cache reuse rejects a known missing expected session. Adjusted analysis OHLC is deterministically derived from the returned Adj Close / Close factor; volumes are never multiplied by this price factor. Missing factors do not imply one. This preserves the historical adjusted chart/technical purpose while retaining a separately identified latest provider raw bar. No second five-year request is added; recovery is a bounded one-session component read when necessary. Provider auto_adjust=False alone does not establish exchange-raw historical split equivalence.

For four-digit TWSE stocks the same producer obtains an exact-date official OHLC/share-volume observation through the existing audited HTTP client. A shared date-keyed six-hour cache and bounded single flight avoid a request per report. Status, response date, named OHLC/volume fields and symbol must match; unavailable, wrong-date, missing-symbol or stale observations cannot be treated as verified. Source URL, field values, raw HTTP response SHA256 and real acquisition timestamp are preserved. The report retains the matched row, not the entire original HTTP response; the hash is not claimed to be an archived body. Cache reuse retains the original acquisition time. No historical availability/PIT claim is created.

A pure per-field ledger compares provider raw OHLC with official raw OHLC, and separately records raw-to-adjusted factors. Price tolerance is max(0.0001, abs(official)*1e-7), solely to accommodate numeric representation; volume tolerance is zero shares. Same ticker/session and finite fields are required. A material official raw-price mismatch blocks the new v4 observation gate. Unequal or missing volume prevents claiming cross-provider volume comparability or using it as a verified cross-provider flow denominator. Yahoo technical volume series stays intact; the official latest volume is not spliced into a Yahoo moving average.

Short-term prompt construction now preserves the recorded price/volume basis and observations while recomputing the pure ledger; observations later than its requested date are excluded. Each technical result records its exact sample window/count and canonical input-bars hash. Existing cache payloads with bars but without the new basis contract are refetched by the normal producer path; no cache purge or full-model rerun is issued.

Report HTML and Markdown share explicit raw OHLC, volume, acquisition-time and source rows. Saved artifacts are not rewritten. Adjusted SMA/ATR/support levels remain analysis prices; official current raw observation does not validate a plan basis, legal quote grid, trigger, fill, taxes, fees or slippage. No executable candidate or realized return is promoted by this ledger.

## Indicator policies and limits

SMA uses the last N validated closes; RSI uses 14 changes with Wilder smoothing; MACD uses SMA-seeded EMA12/26 and EMA9 signal; ATR uses previous-close true ranges with Wilder smoothing. Stored history is bounded to 120 valid bars, and no missing session is synthesized. Report volume_ratio_20 remains latest provider volume divided by the mean of the final 20 provider volumes (includes the latest bar), explicitly recorded in calculation_policy. The screener volume_ratio uses the preceding 20 observed volumes (requires 21 rows); it is a different named filter and must not be numerically equated with report volume_ratio_20. Provider monthly average is separately identified and is not a verified rolling-20-session SMA. All formulas preserve missing-data behavior and source-specific units.

Original 1,688 trade-evaluation payloads and five approved append revisions remain unchanged. The finite approved scope remains 76 (five no-trade, 71 pending). No new schedule, credentials, purchase, order, Git push, full-model batch or external message is created. Three obsolete source-test fixtures were corrected to use current regional applicability and company-linked news; their failures were reproduced on the unchanged canonical baseline before correction.
